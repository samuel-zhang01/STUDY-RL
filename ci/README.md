# Trusted-main local checks

Main pushes and explicit main dispatches use only the dedicated `ci-study-rl` label. The job-level repository/ref/event guard runs before checkout. This listener must have no default labels, and external-contributor approval must be tightened before it comes online. Public pull requests keep the original hosted CPU, browser and redacted-history checks as an explicit free public-repository exception. Main has no hosted fallback. Labels route jobs; they do not isolate trusted repositories sharing a Unix account or root-equivalent Docker authority.

The original Makefile, requirements, tests and browser scenarios stay unchanged. The CPU mode runs `make release-check PY=python` and `make tests PY=python`: every dynamically discovered weekly suite still has its own pytest process, followed by the original optional lab, Python unittest and Node engine targets. An additive pytest plugin requires every collected case to pass without skip, xfail or deselection, including collection skips. Separate accounting requires the original unittest and Node commands actually to execute. Full optional lab requirements are installed; tiny random local Llama/PEFT checks are not replaced by missing-dependency skips.

Browser mode runs `make browser-tests PY=python` with exactly Chromium, Firefox and WebKit. The original scenario function and browser actions/assertions remain untouched. History mode records the exact prebundle ref-to-OID map, event HEAD and reachable-object-set digest from the fetched checkout, exports a credential-free `--all HEAD` bundle, and requires its advertised refs and a second source snapshot to match. The offline worker checks the bundle SHA-256/size, performs a mirror import that preserves remote, notes and custom refs, and checks exact resolved ref/OID equality, detached event HEAD and reachable-object closure before and after the original `make secrets` (`gitleaks git --redact --log-opts="--all --full-history" .`). Full object integrity is checked before the scan. The checkout fetches full history for that job. This covers only refs and history actually present in that fetched checkout; hidden/unfetched GitHub refs, deleted history and cached remote objects are not claimed. No owner Git config, hooks, credentials or HOME is copied. The release checker uses only a fresh temporary tracked index; it is not a GitHub provenance or release-authority claim.

Dependency preparation uses the reviewed AMD64 Python 3.12 and Node 22.22.2 bases, the unchanged requirements and npm lock, and the exact authenticated official CPU Torch 2.14.1 wheel already qualified by the owner's CPU checks. It satisfies the original `torch>=2.6,<3` requirement. Application dependency declarations are unchanged. PyPI transitives remain resolver-selected as in the original workflow; this is not a full Python lock or vulnerability-scan claim. Playwright 1.64.0 installs all three engine bundles and their distro libraries. Gitleaks 8.30.1 retains the original checksum.

Only public dependency manifests and CI support enter the networked dependency-image preparation. There is no application/model source, owner environment, secret, Docker auth config or model fetch in that context. Downloads are not claimed to have registry-only egress. This build uses the shared Docker-daemon resource boundary, not the later test cgroup; it has a 1200-second timeout. Fresh preflight requires load below 6, available RAM at least 8 GiB, runner-filesystem free space at least 15 GiB and actual Docker-storage free space at least 20 GiB. Dependency resolution/build compatibility, first-run disk use and all browser runtime behavior require actual baseline qualification.

Each test container uses UID/GID 10001, read-only root and exact tracked-source input, network none, capabilities zero, no-new-privileges/default seccomp, 1 CPU, 4 GiB without swap, 512 tasks and a fresh bounded 2 GiB noexec tmpfs. The worker checks effective kernel/cgroup state. It copies the public tracked source into private temporary work, retains original content hashes, and never writes the live checkout. Installed native dependencies and browser binaries execute from the dependency image; no execution mount or sandbox flag is weakened. Temporary test/model/cache state is synthetic. No GPU devices, Docker socket, provider key or external route is supplied. Offline flags and network none prohibit pretrained downloads and provider access.

Repository/run/attempt/mode/operation labels and exact names are recorded before object creation. Cleanup checks labels and identities, removes full IDs, verifies both names and IDs absent, and continues other objects after an error. Workflow `always()` reconciliation is scoped to the same mode, so it cannot remove a sibling job's resources. Unknown build/create completion or failed cleanup retains private operation metadata and refuses acceptance; reconcile before another operation. No global prune is performed. Public dependency cache layers may remain. These are routine CI controls, not a separate-host security boundary or a crash-proof transaction guarantee.

TeX/PDF regeneration, notebook execution, optional numerical workbooks, real pretrained-model downloads, actual NVIDIA kernels and deployment remain manual and are not claimed equivalent to these maintained CPU/browser checks. No production or provider workflow is introduced.
